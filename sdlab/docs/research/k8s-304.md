## Why strategies failed 304

**The new feature caused all three non-passes.** The new timeout drain was folded into the move or the
traffic gain on counts-short (cause S1). The new 5xx counter caused nothing: every strategy finds
`inflight -> errors_total` at 0.0296-0.0302 (true 0.03) in every cell. No older cause showed up on 304.

S1, in effect_hats and inflow_effects (identical flows): the pinned main line's `matrix.conserve`, in its
"changing inflows" configuration, reads the queue's drain at 0.9094 against a move of 0.6411 from inflight's
row. That 29.5% gap is just under the 30% slack, so conservation sets the drain to the move and the timeout
becomes 7 constant outflow pieces on queue. Each strategy's resegment and joint refit then shrank the
traffic gain to 0.881 (= 0.6/0.68, the timeout folded into the input), and `prune` dropped the leftover
pieces. A proportional drain was never offered. Result: no timeout, behaviour skill 100%, so "equivalent".

S1, in shared_noise: its own `conserve` took the BIC branch even though the forced fit cost dBIC +3.3 (RSS
239212.3 -> 246521.6, T 299). It was let through by an extra log T allowance on top of the one number the
forced fit saves. The queue drain was folded from 0.7784 to the move 0.6145 in all 8 configurations; traffic
stayed at 1.139 with no drain (skill 94%), "equivalent" only through the wide per-row tolerances.

**Not a failure, but recorded (S2, refuted as a bias).** Every passing counts cell reads the timeout high:
counts-short 0.1879 (22 strategies), 0.1333 (15), 0.1767 (7), and 0.1435, 0.1791, 0.1639 once each;
counts-long 0.133 (22), 0.088 (14), 0.1351 (8), 0.093 (2), 0.1272 (1). Over 40/30 fresh seeds the queue-row
estimator averages 0.0831/0.0785, so seed 304 is a +1.6/+1.9 sd draw, not a bias
([k8s-304-s2.md](k8s-304-s2.md)). These cells pass under the scorer's existing tolerance, which is about
30x the bound on counts cells (known; needs the user's approval to change; not touched).

## Round 1: fixes and flips

Commit **7b6d7f4** (report [k8s-304-s1.md](k8s-304-s1.md), faa169b). Each change lives in the strategy's own
package; no cross-imports.

- **effect_hats/price.py, inflow_effects/price.py** (identical change): `prune()` also tries replacing an
  outside-outflow piece set on a stock X with one proportional drain `X -> outside = k*X` (new
  `_drain_for`), refitted jointly, and keeps it only when the price falls. On 304 counts-short the price
  drops 6544.7 -> 6540.0 and gives timeout 0.1767, traffic 1.139, coflow_hats' passing answer. This is a
  change inside one fit, not a selection.
- **shared_noise/matrix.py `conserve`**: the forced fit is priced at one log T. Option `conserve_allow`
  defaults to 0 (1 restores the old allowance). Writing back the traffic gain, proposed in review 1, was not
  needed: once conservation is rejected the original row stands.

Flips (stored rows, `uv run sdlab-ladder run --strategies effect_hats,inflow_effects,shared_noise --cases
300,301,302,303,304 --jobs 4 --timeout 600`):
- 304 counts-short: effect_hats, inflow_effects, shared_noise equivalent -> pass.
- 300-304 for the three: 72/72 pass; the other 69 cells pass before and after. fail->pass 3, pass->fail 0.

Paired samples, old vs new on the same code with the old behaviour switched back on, nothing stored: 60
random non-k8s cells per strategy, 0 changes each; shared_noise on 49 cells with a drain beside a move, +1
(006-chain-exit-middle counts-short fail -> pass), -0; the hats strategies on 50 cells each whose answer had
outside-outflow pieces, 0 changes. Totals +4, -0.

S2 (round 1, second task): refuted by a seed sweep, no code changed, no flips (k8s-304-s2.md, 4747340).

## Eliminations

Rule: a strategy leaves the competition only for a hard reason, confirmed by two skeptics. "Not fixed yet"
is never a reason. Eliminated strategies stay on the rest of the ladder.

**Impossible: none.** No survivor failed a cell after round 1, so none was a candidate.

**Duplicate: unified, of matrix (confirmed).**
- *Proposal.* Same status and same found model (flows plus rates to 3 significant figures) on every shared
  cell: 438 cells with current-hash rows for both, including all 24 kubernetes cells 300-304, 0 differ; the
  other 710 shared cells re-run in process on current code (`runner.run_item`, single-threaded, nothing
  stored), 0 differ, including every cell where old stored rows disagreed. unified/__init__.py says "WORK IN
  PROGRESS ... identify() returns the main line's model unchanged": it calls `earned.main_line`, a
  byte-identical copy of matrix's, then `eiv.apply`, the same refit matrix carries inline as `_eiv_`.
  Median discovery seconds on 300-304: unified 0.312, matrix 0.096. matrix is kept as the plain, faster
  method.
- *Skeptic (could not refute).* `cmp` shows earned.py, earned_joint.py and earned_rows.py byte-identical to
  matrix's. After stripping docstrings and normalising the `_eiv_` prefixes in the AST, unified/eiv.py and
  matrix's inline code differ only in import aliasing, `from __future__ import annotations` and a class name.
  identify() never imports unified's other modules (codetable, frontend, engine, kalman, objective, price).
  The 8 shared cells whose stored statuses differ (125, 200 x2, 201, 215, 216 x2, 226) were re-run for both
  in process: identical status and flows on all 8. No mechanism one has and the other lacks, so they will
  match on the remaining rungs.
- *Record.* The elimination only drops unified from the competition. Its package stays: 
  `sdlab/ladder/objective_test.py` and `objective_labels.py` import its frontend, codetable, objective and
  price. If unified's own search is built, it is no longer a duplicate and can come back.

**Duplicate: blockwise, of matrix (refuted, blockwise stays).**
- *Proposal.* Same status and model on 446 current-hash shared cells (all 24 of 300-304) and on the 13
  cells where old rows disagreed, re-run on current code. blockwise/__init__.py runs matrix's main line

- *Skeptic (refuted).* (1) The store already holds shared cells where the found models differ: on the four
